## 1. Executive summary

The codebase is clean at the surface:

- **Frontend:** type-checks, lints with no warnings, its 16 tests pass, and it builds.
- **Backend:** all **494 tests pass**, and the CDK app synthesizes. All 14 stacks are deployed.

The surface hides the real state. **Against the real backend, the system cannot complete a single authenticated user journey.** Four independent defects each block it:

1. **Nobody can sign in.** The PWA requests the OAuth scope `phone`, which the Cognito app client does not allow. Cognito rejects every login with `invalid_scope`. This is confirmed live (SYS-01).
2. **Payment never confirms.** In dev the backend returns a fake Fapshi URL and never calls Fapshi. The webhook lookup is also broken (it uses `Scan` with `Limit=1`). Consultations therefore never reach the doctor queue (SYS-02, SYS-03).
3. **The deployed backend is empty.** There are 0 facilities, 0 users and 0 translations. The facility seed script crashes on its first row, and the facility API would crash on seeded data (SYS-04).
4. **Push notifications are wired wrong at every layer.** The field names don't match, the key is a placeholder, the library isn't packaged, and nothing emits the trigger events (SYS-09).

The demo path works only in **mock mode**, where `mock.ts` simulates payment confirmation, push and seeded data. The committed `Frontend/.env` switches mock mode **off**, so a fresh clone runs `npm run dev` against the live backend and fails at sign-in.

Beyond the blockers, there are serious **authorization holes**:

- any signed-in user can post messages, including messages posing as a doctor, into any consultation;
- anyone on the internet can mark a consultation paid;
- the payer chooses the amount;
- voice notes can be read across consultations.

There are also two **clinical-safety defects** in the triage rules (SYS-12, SYS-13).

## 3. Critical findings

### SYS-01 🔴 Sign-in is impossible against the deployed Cognito

- **Where:** [session.ts:28](../Frontend/src/auth/session.ts#L28) requests `scope: "openid email phone profile"`. [auth_stack.py:56](../Backend/health_track/auth_stack.py#L56) allows only `EMAIL, OPENID, PROFILE`.
- **Evidence (live):** the same `/oauth2/authorize` request with `phone` redirects to `…/auth/callback?error=invalid_request&error_description=invalid_scope`. Without `phone`, Cognito shows the login page.
- **Impact:** every authenticated feature is dead on the real backend: profile, triage sync, consultations, payment and the doctor console.
- **Fix:** remove `phone` from the scope (one word), or add `OAuthScope.PHONE` and redeploy.

### SYS-02 🔴 Anyone can mark a consultation "paid", and nothing legitimate ever does

- **Where:**
  - [post_webhook.py:30-35](../Backend/health_track/lambdas/payment/post_webhook.py#L30) skips signature verification when `ENV_NAME == "dev"`, and dev is the only deployed environment.
  - The route is public ([payment_stack.py:156](../Backend/health_track/payment_stack.py#L156)).
  - [post_initiate.py:50-54](../Backend/health_track/lambdas/payment/post_initiate.py#L50) returns `fapshi_ref = "sandbox-<8 chars>"` to the caller.
- **Impact:**
  - A user POSTs `{"transId": "<their ref>", "status": "SUCCESSFUL"}` and gets a free consultation.
  - Conversely, the dev `payment_url` (`https://fapshi.com/pay/sandbox/…`) is a dead page and Fapshi is never called. Only the frontend mock ([mock.ts:412-427](../Frontend/src/api/mock.ts#L412)) simulates confirmation.
- **Fix:**
  - Never trust the webhook body. Re-query Fapshi's payment-status API with the transaction id before marking anything paid.
  - Add an Admin-only "simulate payment" endpoint for demos.
  - Check the Fapshi docs: it is not confirmed that Fapshi sends an `x-fapshi-signature` HMAC at all, so the non-dev branch may reject every real webhook.

### SYS-03 🔴 Webhook cannot find the payment once the table has more than one row

- **Where:** [post_webhook.py:50-58](../Backend/health_track/lambdas/payment/post_webhook.py#L50) runs `scan(FilterExpression="fapshi_ref = :ref", Limit=1)`.
- **Why:** DynamoDB applies `Limit` **before** the filter. It reads one item, filters it, and returns nothing unless the match happened to be first. The handler then returns `200 acknowledged`, so Fapshi stops retrying.
- **Impact:** real payments are silently lost. The patient pays and the case never reaches a doctor.
- **Fix:** look up by primary key. The code already sends `externalId = payment_id` to Fapshi, so use `get_item(payment_id=payload["externalId"])`, or add a `fapshi_ref` GSI.

### SYS-04 🔴 Facility data can't be seeded, and seeded data would crash the API

- **Where:**
  - [seed_facilities.py:21](../Backend/scripts/seed_facilities.py#L21) and the rows after it pass Python floats (`"latitude": 4.1527`) to boto3. **Verified:** `Float types are not supported. Use Decimal types instead.` The script dies on the first row.
  - It also defaults to `--region af-south-1` ([line 698](../Backend/scripts/seed_facilities.py#L698)), but the stack lives in us-east-1. `seed_i18n.py` has the same problem.
  - Once seeded, `capabilities` is a DynamoDB String Set, and [response.py:8-11](../Backend/lambda_layers/common/python/health_track_common/response.py#L8) cannot serialize a `set`. **Verified:** `GET /facilities` and `GET /facilities/{id}` would return 500.
- **Impact:** the live facility API returns `[]`. The PWA survives only because it bundles its own seed JSON. Every server-side feature that uses facilities is empty: blood-bank lookup, referrals to a named facility, the operator console.
- **Fix:** use `Decimal(str(x))` in the seed script, handle `set` in `_json_default`, and run both seeders against the right region as part of deploy.

### SYS-05 🔴 Any signed-in user can write into any consultation, including as "doctor"

- **Where:**
  - [post_message.py:49-57](../Backend/health_track/lambdas/consultation/post_message.py#L49) checks only that the consultation _exists_. It does not check ownership or the assigned doctor.
  - [post_sync.py:77](../Backend/health_track/lambdas/consultation/post_sync.py#L77) takes `sender_role` **from the client** (`msg.get("sender_role", "patient")`) and doesn't check that the consultation exists.
- **Impact:** patient A can inject messages, including fake "doctor" advice, into patient B's medical conversation. On a health platform this is the most dangerous finding in the audit.
- **Fix:** load the consultation and require `phone_owner_id == sub`, or Doctor group membership with `doctor_id == sub`. Always set `sender_role` on the server.

### SYS-06 🔴 Payer chooses the amount

- **Where:**
  - [post_initiate.py:44](../Backend/health_track/lambdas/payment/post_initiate.py#L44): `amount_xaf = int(body.get("amount_xaf", 2000))`. Zero and negative values are accepted, and a non-numeric value returns 500.
  - The anonymous version accepts 1 to 1,000,000.
  - The webhook copies `payload["amount"]` into the receipt and never compares it.
- **Impact:** once real Fapshi is enabled, a consultation costs whatever the client sends.
- **Fix:** compute the fee on the server (from config or the facility's `consultation_fee_xaf`, which the frontend reads but no backend code uses). Require `paid amount == expected` in the webhook.

### SYS-07 🔴 Patients can forge `patient_id` and `urgency`, which lets them inject records and jump the queue

- **Where:** [post_consultation.py:33](../Backend/health_track/lambdas/consultation/post_consultation.py#L33) uses `patient_id = body.get("patient_id") or user_id`. [Lines 43-48](../Backend/health_track/lambdas/consultation/post_consultation.py#L43) store any `urgency` string, unrelated to the linked triage result. `on_behalf_member_id` isn't validated against the household.
- **Impact:**
  - Anyone can self-declare RED and jump the doctor queue.
  - Records can be written into another user's `PatientIndex`.
  - A missing urgency is stored as `urgency_created = "None#<ts>"`.
- **Fix:** derive `patient_id` on the server. Read urgency from the server-stored triage result, after checking its owner.

### SYS-08 🔴 The committed `Frontend/.env` switches off mock mode and bakes in localhost

- **Where:** `Frontend/.env` is tracked (added in `070e66f`) even though [.gitignore:27](../Frontend/.gitignore) lists it. It sets 7 live API URLs plus Cognito, and `VITE_COGNITO_REDIRECT_URI=http://localhost:5173/auth/callback`.
- **Impact:**
  - The README's promise ("with no .env the app runs fully on its mock API") is false.
  - A fresh clone runs live mode, which dies at SYS-01.
  - Every build hard-codes a localhost redirect. [env.ts:27](../Frontend/src/config/env.ts#L27) uses `??`, so the `window.location.origin` fallback never applies.
  - No secrets leak: a Cognito client id and API URLs are public by nature.
- **Fix:** `git rm --cached Frontend/.env`, set the variables per environment in CI, and change `??` to `||`.

## 7. Contract matrix (frontend → backend)

All 25 frontend calls map to a deployed route; none returns 404. Field casing is snake_case on both sides. The mismatches are semantic:

| Call                                          | Status                                                                    |
| --------------------------------------------- | ------------------------------------------------------------------------- |
| Profile get/update, household add/remove      | ✅ Matches                                                                |
| Facilities list/get                           | ⚠️ Matches, but the server returns `[]` (SYS-04)                          |
| `POST /triage`                                | ⚠️ Server ignores the client id (SYS-16)                                  |
| `POST /sync`                                  | ⚠️ Shape matches; trusts `sender_role` (SYS-05)                           |
| Consultations list/create/get, messages       | ⚠️ Shape matches; on-behalf list broken (SYS-11), urgency forged (SYS-07) |
| Voice upload/download URL                     | ⚠️ Works in us-east-1; authorization gap (SYS-10)                         |
| Payments initiate/get                         | ❌ Never confirms in dev (SYS-02/03)                                      |
| Doctor queue/case/claim/close/prescribe/refer | ⚠️ Shape matches; reachable only after SYS-01 and SYS-02 are fixed        |
| Prescription/referral lookup (public)         | ✅ Works live                                                             |
| Push key/subscribe                            | ❌ Field mismatch both ways (SYS-09)                                      |
| Unsubscribe                                   | ✅                                                                        |

**Built on the backend but never called by the frontend** (30+ routes):

- the entire Anonymous API (6 routes);
- Channel (5 routes);
- Extended (18 methods: appointments, lab, blood, emergency, tips, presence, available doctors);
- I18n;
- `GET /triage`, `GET /payments`, and facility admin.

The frontend has no URL variable for 4 of the 11 APIs.

**`mock.ts` hides real behaviour.** It does all of the following, which the real backend does not:

- auto-confirms payment after 3 s;
- uses different push field names;
- filters consultations by `phone_owner_id`;
- auto-creates the profile;
- returns non-empty facilities;
- skips S3 for voice notes.

The integration plan ([plan, line 379](../docs/superpowers/plans/2026-10-22-frontend-backend-integration.md)) intended to replace the local triage id with the server's; the code never did.
